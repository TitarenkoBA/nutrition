# Сайт нутрициолога

Статический сайт на [Astro](https://astro.build), публикуется на GitHub Pages. Своего сервера нет.

| Адрес | Что это |
|---|---|
| `/` | Лендинг |
| `/anketa/` | Анкета клиента. Заполняется в браузере, в конце — PDF и отправка в Telegram / на почту |
| `/blog/` | Блог |
| `/privacy/` | Политика конфиденциальности (шаблон — проверьте текст) |
| `/admin/` | Админка: тексты сайта и статьи блога |
| `/kabinet/` | Закрытый раздел: справочник с поиском и документы, по паролю |

## Запуск на компьютере

Нужен Node.js **24** (LTS). Скачать: https://nodejs.org

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # сборка в dist/
```

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и отправьте туда код (ветка `master`).
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Каждый push в `master` автоматически пересобирает и публикует сайт
   (`.github/workflows/deploy.yml`). Адрес: `https://<логин>.github.io/<репозиторий>/`.

Адрес сайта и имя репозитория для админки подставляются сами — ничего настраивать не нужно.

## Админка (`/admin/`)

Используется [Sveltia CMS](https://github.com/sveltia/sveltia-cms) — совместима с Decap CMS,
но умеет входить без отдельного сервера авторизации.

Вход:
1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Repository access: только репозиторий сайта. Permissions → **Contents: Read and write**.
3. На странице `/admin/` выберите **Sign In Using Access Token** и вставьте токен.

Что можно редактировать: контакты (Telegram, e-mail — **сюда клиенты отправляют анкету**),
все блоки главной, цены, отзывы, вопросы, статьи блога с картинками.
Каждое сохранение — это коммит в репозиторий; через 1–2 минуты сайт обновится.

Без админки то же самое можно править в файлах:
`src/content/site/settings.json`, `src/content/site/home.json`, `src/content/blog/*.md`.

## Анкета

Вопросы — в `src/components/questionnaire/schema.ts` (по ним строятся и форма, и PDF).
Ответы никуда не отправляются: черновик хранится в браузере клиента, PDF создаётся там же.

## Закрытый раздел (`/kabinet/`)

GitHub Pages не умеет закрывать страницы паролем, поэтому материалы **зашифрованы**
(AES-256-GCM, ключ из пароля через PBKDF2, 600 000 итераций) и расшифровываются в браузере.
Без пароля файлы в `public/vault/` бесполезны, их можно хранить в публичном репозитории.

Исходники лежат в папке `private/` — она **не попадает в git** (см. `.gitignore`):

```
private/
  files/            ← PDF-документы (название в кабинете = имя файла)
  handbook.mjs      ← справочник с поиском (можно править)
  .vault-password   ← пароль
```

После любых изменений в `private/`:

```bash
npm run vault      # зашифровать заново → public/vault/
```

и закоммитьте `public/vault/`.

**Сменить пароль:** впишите новый в `private/.vault-password` (не короче 12 символов) и запустите `npm run vault`.

> ⚠️ Сделайте резервную копию папки `private/` (например, в личное облако):
> её нет в репозитории, и без пароля зашифрованные файлы не восстановить.

В справочнике записи с пометкой **«⚠ проверить»** — места, где в исходных PDF, похоже,
опечатка или ошибка. Проверьте их и удалите поле `check` в `private/handbook.mjs`.
